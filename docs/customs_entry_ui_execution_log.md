## Friction Points
| Area | Friction | Impact | Recommendation |
| --- | --- | --- | --- |
| House Bill format | LDS rejects punctuation like `HB-123456` and only allows `A-Z`, `0-9`, and space | Operators discover this only after submit | Add local regex validation and inline helper text on `house_bill` / `master_bill` |
| Line Item Identifier length | LDS enforces max length `3` for `LineItemIdentifier` | Article entry fails late during submit | Add local max-length validation and help text on article line item identifier |
| Shipment numbering | LDS shipment `Number` behaves like a globally unique internal identifier and collides across reruns | Manual testing and repeated entry are brittle | Auto-generate shipment internal numbers for drafts, or provide a server-side allocator/action |
| Post-submit rename | Successful submit renames draft documents to final entry numbers | UI automation and potentially operators can lose context | Surface a post-submit success banner with old draft -> final entry mapping and redirect explicitly |
| Carrier display on readback | LDS returns linkage more reliably than display labels for shipment carrier context | Reviewers may think carrier data was lost when only the label is missing | Show carrier code/id-backed display fallback in review UI and verifier |
| Duty amount null vs zero | LDS may omit zero duty amounts on readback | Verification can show false mismatches | Treat null and zero as equivalent in UI review and verification layers |
| Importer / carrier master creation | First-time entry of a new importer or carrier still requires opening and submitting separate master records before the entry can proceed smoothly | Entry clerks lose flow and repeat master data context switching | Add inline “Create missing importer” / “Create missing carrier” actions from the entry form, with return-to-entry behavior |
| Shipment / invoice identifiers in repetitive testing | Reusing visible shipment or invoice numbers across runs collides with LDS uniqueness expectations | Repeat entry work is error-prone and opaque | Auto-suggest unique shipment and invoice identifiers for drafts, while still allowing operator override |
| Stale master reuse | Reusing an old synthetic carrier record can hide newly entered fields and cause mode-specific LDS failures | Operators may trust a master record that is incomplete for the transport mode they are entering | Show a mode-readiness check on selected carrier/importer records and warn before submit when required master fields are missing |
| Air carrier setup | Air shipments need more than a generic carrier create; the carrier must be air-typed and carry an airway bill prefix | Air entry fails late unless the master record is prepared correctly | Add carrier-type-specific field groups, required-field validation before carrier submit, and an “air-ready” badge on carrier records |
| Multi-invoice linkage | Once an entry has multiple invoices, the operator has to mentally track which article and tariff belong to which invoice row | Article/tariff entry gets slower and easier to mis-key | Add invoice-context display or filter when entering articles and tariffs, and default new article rows to the currently selected invoice |
| AD/CVD clarity | AD/CVD cases are operationally distinct but currently entered through almost the same UI rhythm as standard consumption entries | Operators get little context that they are in a higher-risk special-case entry | Add entry-type-specific cues, validations, and helper text when `entry_type = 03` |
| Login boundary flake | Immediately starting a new browser case after another one can occasionally land on `/login` without a fully initialized `window.frappe` context on the first attempt | Automated and possibly very rapid operator flows can fail before entry even begins | Add a more defensive login/bootstrap wait in the UI test harness and consider a lightweight readiness indicator in the Desk shell |
| Submit failure persistence deadlock | A failed submit path can deadlock while saving `lds_submission_errors`, not just on the final `submit()` step | Operators can lose the real LDS validation message and be left with an infrastructure-style failure instead of a business error | Keep deadlock retry handling on failure-state persistence and the pre-submit save path, and surface a clearer retryable error message if all retries exhaust |
| Concurrent UI sessions | Running two Playwright cases at the same time with the same ERPNext automation user pushed one session back to `/login` or into a partially initialized Desk context | Parallel UI execution becomes flaky even when the underlying data path is healthy | Use one dedicated test user per worker or force serial execution for reliable operator-flow automation |
| Lookup readiness after rapid reruns | When cases are run back-to-back, a transient login/bootstrap failure can mask a healthy data path for new entry types like warehouse | Test execution and rapid operator retesting can waste time on non-business failures | Harden the login/bootstrap path and add a quick readiness probe before starting a new entry form |
| Warehouse type guidance | Warehouse entries currently use the same generic form as consumption and informal entries, with no extra guidance about what makes them different operationally | Operators get little help distinguishing a rare warehouse filing from more common entry types | Add entry-type-specific guidance and field emphasis when `entry_type = 21`, similar to the recommendation already logged for AD/CVD |
| New HTS discoverability | The new-HTS scenario succeeded, but only with pre-resolved symbolic mapping rather than a user-friendly HTS search experience in the form | Operators may not be able to find unfamiliar valid tariff codes efficiently | Add HTS code search/autocomplete with authoritative descriptions and recent/likely matches |
| New port discoverability | The new-port scenario worked only because the symbolic mapping was pre-resolved in the test harness; the UI itself still depends on prior knowledge of what port codes to search for | Operators can struggle when they need a valid but unfamiliar port | Improve port lookup search and display richer labels, including code + city/state/name, with better empty-state guidance |
| New master-data context switching | Cases that require a new importer or carrier still force the operator into a separate create-submit-return loop before the entry can continue | First-time party setup breaks the operator’s flow and increases data re-entry risk | Add inline create-and-return flows for importer and carrier from inside the Customs Entry form, preserving the partially entered draft context |
| Shipment number semantics | Mixed-shipment structure cases were unstable until shipment numbers were changed from alphanumeric values to numeric-only values | Operators have no clear guidance that LDS appears to treat shipment `Number` as a numeric internal identifier rather than a free-form reference | Validate shipment number format locally, auto-generate a safe numeric default, and keep any human-facing shipment reference in a separate field |
| Deadlock retry state loss | A deadlock during the pre-submit save path originally reloaded the draft from DB and discarded the in-memory LDS-mapped state before submit | Large entries could end up submitted locally with a temporary entry number and no LDS linkage | Preserve the in-memory mapped state across retries and add regression tests around deadlock recovery for large entries |
| Server-side timestamp drift during submit | Large capstone entries can hit a false stale-document error between initial draft save and the server-side pre-submit save | Operators get blocked by a refresh-style error even though the only writer is the controlled submit pipeline | Refresh the server-side modified baseline immediately before controlled save/submit attempts, while keeping normal user-facing stale-edit protection intact |
